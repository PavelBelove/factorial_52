# Роли агентов и система квантов PlexMem

**Дата:** 2026-01-19  
**Статус:** Техническая спецификация

---

## 1. Архитектура системы

PlexMem использует **предиктивно-ассоциативную память** на основе квантов.

### Четыре агента:

1. **Game Master (ГМ)** - ведет игру, отыгрывает мир
2. **Quantizer (Квантователь)** - управляет памятью, создает/обновляет кванты
3. **Summarizer (Суммаризатор)** - сжимает историю
4. **Translator (Переводчик)** - оптимизирует контекст, экономит 40-50% токенов

---

## 2. Game Master (ГМ)

### ЧТО ДЕЛАЕТ:
- Ведет повествование от 2-го лица
- Создает живой мир и отыгрывает NPC
- **Запрашивает существующие кванты** для следующего хода
- Отвечает игроку естественным текстом
- **Возвращает результаты хода:** успешные проверки, изменения статов, инвентаря
- Передает изменения менеджеру игровых механик

### ЧТО НЕ ДЕЛАЕТ:
- ❌ НЕ создает кванты
- ❌ НЕ изменяет кванты
- ❌ НЕ использует маркеры `=` в ответе игроку
- ❌ НЕ придумывает новые имена квантов

### КАК РАБОТАЕТ С МАРКЕРАМИ:

**ГМ ВИДИТ маркеры в контексте:**
```
# Доступные кванты:
- Лира: Магистр =Академия_Рендала= отец =Отец_Лиры=
- Кири: студентка =Факультет_Иллюзий= флиртует с =Пол=
```

**ГМ ПОНИМАЕТ:**
- `Лира` - существует, можно запросить
- `Академия_Рендала` - существует (видит в маркерах), можно запросить
- `Отец_Лиры` - существует, можно запросить

**ГМ ПИШЕТ игроку (БЕЗ маркеров):**
```
Лира встречает тебя в Академии Рендала. Она говорит 
об отце, пропавшем в Зачарованном Лесу.
```

**ГМ ЗАПРАШИВАЕТ на следующий ход:**
```json
{
  "reply": "...",
  "quants": ["Лира", "Академия_Рендала", "Отец_Лиры", "Зачарованный_Лес"]
}
```

### КРИТИЧНО:
- Маркеры `=Имя=` - это **метаинформация** для ГМ
- ГМ их **видит** чтобы понять какие кванты существуют
- Но **НЕ использует** в своем ответе игроку
- Игрок **не видит** маркеры

---

## 3. Quantizer (Квантователь)

### ЧТО ДЕЛАЕТ:
- Создает кванты для всего важного из диалога
- Обновляет существующие кванты новой информацией
- Создает **двунаправленные связи** между квантами
- Заполняет **синопсисы** с максимумом контекста и отсылок

### ЧТО НЕ ДЕЛАЕТ:
- ❌ НЕ участвует в диалоге с игроком
- ❌ НЕ выбирает активные кванты (это делает ГМ)

### КАК ВЛИЯЕТ НА СТИЛЬ (косвенно):
- Использует **культурные референсы** для создания живых образов
- Вместо длинного описания: `"reference": "Холо из Волчица и пряности, но лисичка"`
- Создает **стабильный образ** в несколько токенов
- ГМ понимает характер по референсу, но не ссылается напрямую в ответе

### КАК ИСПОЛЬЗУЕТ МАРКЕРЫ:

**Структура кванта с synopsis:**
```json
{
  "id": "Кири",
  "type": "npc",
  "synopsis": "миниатюрная девушка-лиса, студентка =Академия_Рендала=, =Факультет_Магии_Иллюзий=, флиртует с =Пол=",
  "body": {
    "role": "студентка академии, 3 курс",
    "reference": "Холо из Волчица и пряности, но лисичка",
    "appearance": "миниатюрная девушка с пушистым лисьим хвостом и ушками",
    "personality": "игривая, кокетливая, любопытная",
    "affiliation": "=Академия_Рендала=, =Факультет_Магии_Иллюзий="
  },
  "links": {
    "Пол": "флиртует, хочет потренироваться вместе",
    "Академия_Рендала": "студентка, 3 курс",
    "Факультет_Магии_Иллюзий": "специализация иллюзии",
    "Элина": "подруга по общежитию"
  }
}
```

**ВАЖНО:**
- `synopsis` - это **ПОЛЕ В КВАНТЕ** (на уровне root, не в body)
- Synopsis **извлекается** системой в "список доступных квантов"
- ГМ видит synopsis как краткое описание, но может запросить полный квант

**В links (связях):**
```json
{
  "links": {
    "Пол": "флиртует, хочет потренироваться вместе, интересуется его оружием",
    "Академия_Рендала": "студентка, 3 курс",
    "Факультет_Магии_Иллюзий": "специализация",
    "Элина": "подруга по общежитию, вместе ходят на занятия",
    "Лира": "преподаватель, уважает"
  }
}
```

**В synopsis (ОБЯЗАТЕЛЬНОЕ ПОЛЕ):**
```json
{
  "synopsis": "миниатюрная девушка-лиса, студентка =Академия_Рендала=, =Факультет_Магии_Иллюзий=, флиртует с =Пол=, подруга =Элина="
}
```

### ТРЕБОВАНИЯ К СИНОПСИСУ:

**ОБЯЗАТЕЛЬНО:**
- Одна строка
- Максимум контекста
- Максимум отсылок на другие кванты через `=маркеры=`
- Отвечает на вопросы: кто? где? зачем? с кем связан?

**❌ ПЛОХОЙ синопсис:**
```
"synopsis": "студентка"
```
Или:
```
"synopsis": ""  // пусто
```

**✅ ХОРОШИЙ синопсис:**
```
"synopsis": "миниатюрная девушка-лиса, студентка =Академия_Рендала=, =Факультет_Магии_Иллюзий=, флиртует с =Пол=, подруга =Элина=, мастер иллюзий"
```

**Почему это важно:**
- ГМ видит список синопсисов
- По синопсису ГМ понимает КТО это и КОГДА этот квант нужен
- Синопсис без контекста бесполезен

---

### ТРЕБОВАНИЯ К СВЯЗЯМ (links):

**КРИТИЧНО:**
- Связи **двунаправленные** (если А связан с Б, то Б связан с А)
- Связи **контекстные** (не просто "знает", а "подруга по общежитию, вместе учатся")
- Связи **обновляются** по мере развития сюжета

**❌ ПЛОХИЕ связи:**
```json
{
  "links": {
    "Пол": "знает",
    "Элина": "знакома"
  }
}
```

**✅ ХОРОШИЕ связи:**
```json
{
  "links": {
    "Пол": "флиртует, хочет потренироваться вместе, интересуется его гранатами и дроном, несколько раз приглашала на чай",
    "Элина": "подруга =Общежитие_Академии=, вместе ходят на занятия =Факультет_Магии_Иллюзий=, обсуждают парней"
  }
}
```

**Почему это важно:**
- Связь передает МАКСИМУМ контекста
- ГМ видит связь и понимает ПРИРОДУ отношений
- Связь помогает различить персонажей

---

### ПРАВИЛА ИМЕНОВАНИЯ КВАНТОВ:

**КРИТИЧНО: 1 сущность = 1 квант!**

Перед созданием нового кванта Quantizer **ОБЯЗАН:**
1. Проверить Active quants - нет ли уже такого?
2. Проверить список синопсисов - может уже создан?
3. Если найден для этой сущности - **обновить существующий**, НЕ создавать новый

**Имя должно быть:**
1. **Полным** - самодостаточным
2. **Однозначным** - понятно что это
3. **Без пробелов** - используй подчеркивания
4. **Консистентным** - одна сущность = одно имя навсегда

**❌ ПЛОХО:**
- `Лунная` - что это?
- `Карта` - какая карта?
- `Мастер` - какой мастер?
- `Квест` - какой квест?

**✅ ХОРОШО:**
- `Город_Лунная_Гавань`
- `Карта_Гильдии_Авантюристов`
- `Гильдмастер_Торгард`
- `Квест_Поиск_Отца_Лиры`

## 4. Summarizer (Суммаризатор)

### ДВА РЕЖИМА РАБОТЫ:

**1. APPEND режим (по умолчанию):**
- Добавляет последние события к существующему summary
- Используется когда summary < 20000 символов
- Быстрое обновление без переписывания всего
- Промпт: `summarizer_system_append.md`

**2. REWRITE режим (полная просушка):**
- Переписывает весь summary заново
- Используется когда summary >= 20000 символов
- Сжимает всю историю в компактный формат
- Промпт: `summarizer_system_rewrite.md`

### ЧТО ДЕЛАЕТ:
- Сжимает историю диалога
- Сохраняет ключевые события
- **Выделяет имена квантов маркерами** `=Имя=` как **якоря**
- Создает семантические связи в тексте summary
- Приоритет маркерам - для самых важных квантов сюжета

### КАК ИСПОЛЬЗУЕТ МАРКЕРЫ:

**Пример summary:**
```
Пол прибыл в =Город_Рендал= и поступил в =Академия_Рендала=. 
Декан =Лира= дала рекомендацию. Пол получил задание зачистить 
=Подгорье= от гоблинов. В пути встретил караван торговца 
=Эрик=, спас его от =Отряд_Работорговцев=. Убил =Тролль_Вожак= 
газовыми гранатами. Вернулся в =Гильдия_Авантюристов=, 
сдал квест =Торгард=.
```

**Зачем маркеры в summary:**
- ГМ видит summary
- Маркеры показывают ГМ какие кванты существуют
- ГМ может запросить эти кванты, чтобы быстро вернуться к важным событиям предыдущего контекста

## 4.5. Translator (Переводчик)

### РОЛЬ И ЦЕЛЬ:

Translator - это служебный агент для **оптимизации контекста**. Работает **в фоне** после каждого хода.

**Цель:** Сократить размер контекста на 40-50% токенов для экономии при загрузке в контекст.

### ЧТО ДЕЛАЕТ:

1. **Получает на вход:**
   - Ход пользователя (user_message)
   - Ответ ГМ (agent_reply)

2. **Структурирует в JSON:**
   ```json
   {
     "turn": 42,
     "player_action": "Player entered tavern, ordered ale, asked about rumors",
     "gm_narrative": "Barkeep tells about missing merchant caravan...",
   }
   ```
   Важно - это не строгий Json а форматированный json-подобным синтаксисом структурированный перевод, форма свободная. Просто для удобства восприятий LLM. Перевести нужно только нарратив

3. **Переводит на английский** - английский токенизируется эффективнее

4. **Сжимает (просушивает):**
   - Убирает **предлагаемые варианты** ("Ты можешь 1) сделать X 2) сделать Y")
   - Убирает **чрезмерно вычурные эпитеты** и длинные описания
   - **Сохраняет** детали, важные для контекста
   - **Сохраняет** эмоции и настроение сцены
   - **Сохраняет** детали внешности NPC, описания сцен, просушивая но не отпуская нюансы.

5. **Сохраняет в БД** как ход (используем в контексте ГМ, суммаризатора и квантователя)

### КАК ИСПОЛЬЗУЕТСЯ:

**В контексте для Summarizer и Quantizer:**
- Вместо полных русских ходов загружаются compressed English JSON
- Экономия 40-50% токенов
- Summarizer и Quantizer получают всю нужную информацию

**ГМ ВИДИТ** translated JSON - он работает с переведенными ходами и summary.

### ПРИМЕР:

**До (русский, ~200 токенов):**
```
Игрок: Я подхожу к бармену и спрашиваю про слухи

ГМ: Ты входишь в таверну "Пенный Кабан". Воздух пропитан 
запахом эля и жареного мяса. Трактирщик Болд, крупный 
мужчина с седой бородой, вытирает кружки за стойкой.
— Добро пожаловать, путник! — гремит он. — Что желаете?
Ты заказываешь эль и спрашиваешь о слухах.
Болд хмурится: — Неделю назад пропал караван...
Варианты: 1) Расспросить подробнее 2) Отправиться искать
```

**После (английский JSON, ~100 токенов, экономия 50%):**
```json
{
  "turn": 42,
  "player_action": "Approached barkeep, asked about rumors",
  "gm_narrative": "Entered =Таверна_Пенный_Кабан=. =Трактирщик_Болд= (burly, grey beard) says merchant =Караван_Торговцев= vanished week ago near forest",
}
```

### КРИТИЧНО:

- ❌ НЕ участвует в диалоге с игроком
- ❌ НЕ влияет на стиль ГМ (работает после ответа)
- ✅ Только оптимизирует хранение и контекст
- ✅ Работает прозрачно для всех агентов

## 5. Система маркеров `=Имя=`

### ТРИ КОНЦЕПТА:

| Концепт | Пример | Кто видит | Кто использует |
|---------|--------|-----------|----------------|
| **Маркер** | `=Академия_Рендала=` | ГМ, Quantizer, Summarizer | Quantizer, Summarizer |
| **ID кванта** | `Академия_Рендала` | Система | Все (в БД и запросах) |
| **Отображаемое имя** | `Академия Рендала` | Игрок | ГМ (в ответе) |

### ДВЕ МЕХАНИКИ ИСПОЛЬЗОВАНИЯ МАРКЕРОВ:

**1. Маркер в тексте (включение имени в контекст):**
```
Summary: "Пол поступил в =Академия_Рендала=. =Лира= дала рекомендацию."
```
- Маркер **включает имя кванта** непосредственно в текст
- ГМ видит маркер → понимает что квант существует
- Можно запросить этот квант

**2. Формат key:value (в JSON):**
```json
{
  "synopsis_list": {
    "Кири": "студентка =Академия_Рендала=, флиртует с =Пол="
  },
  "inventory": {
    "Меч_Катана": "оружие, +20 к атаке, можно призывать =Магией_Призыва="
  },
  "links": {
    "Пол": "флиртует, учится вместе в =Академия_Рендала="
  }
}
```
- **Ключ** (Кири, Меч_Катана, Пол) - это ID кванта
- **Значение** - описание, которое МОЖЕТ содержать маркеры на другие кванты
- Маркеры в значении **усиливают семантику** и создают связи

### ГДЕ ИСПОЛЬЗУЮТСЯ МАРКЕРЫ:

**✅ Используют:**
1. **Quantizer** - в квантах (body, links, synopsis)
2. **Summarizer** - в summary как **якоря** к ключевым квантам прошлого

**❌ НЕ используют:**
3. **Game Master** - НЕ использует в ответе игроку
4. **Код системы** - не обрабатывает маркеры напрямую (это для агентов)

### ЗАЧЕМ НУЖНЫ МАРКЕРЫ:

1. **Для ГМ** - видеть какие кванты существуют, навигация
2. **Для Quantizer** - создавать семантические связи между квантами
3. **Для Summarizer** - сохранять якоря к ключевым квантам в истории
4. **Для семантики** - усиливать связность и контекстность описаний

## 6. Поток данных

### Ход игры:

```
1. Игрок пишет сообщение
   ↓
2. ГМ получает контекст:
   - **System prompt** - инструкции ГМ
   - **Summary** (с маркерами =Имя= как якоря)
   - **Active quants** (полные кванты: id, type, synopsis, body, links)
   - **Synopsis list** (формат: "Имя_Кванта": "описание с =маркерами=")
   - **Inventory** (формат: "Предмет": "краткие характеристики")
   - **Game mechanics data** (карты, статы, инвентарь, проверки)
   - **Recent turns** (последние 5-7 ходов диалога)
   ↓
3. ГМ анализирует контекст:
   - **В summary** видит маркеры =Имя= → понимает что квант существует
   - **В synopsis list** читает "Имя": "описание с =маркерами=" → понимает суть и связи
   - **В Active quants** читает full body → использует все детали в повествовании
   - **В Inventory** видит предметы → может упомянуть, ГМ может запросить как квант
   - **В mechanics data** видит карты/статы → объявляет проверки
   ↓
4. ГМ отвечает игроку:
   - **Narrative** - текст БЕЗ маркеров (игрок не видит маркеры)
   - **Quant requests** - 5-10 квантов для следующего хода (без маркеров)
   - **Response data** - изменения статов/инвентаря для mechanics manager
   ↓
5. Quantizer обрабатывает диалог:
   - Создает новые кванты (проверяя дубликаты!)
   - Обновляет существующие
   - Создает/обновляет связи (двунаправленные!)
   - Заполняет synopsis с максимумом маркеров
   - **Создает кванты для предметов из inventory**
   - Использует культурные референсы для NPC
   ↓
6. Summarizer обновляет summary:
   - Сжимает историю
   - Выделяет кванты маркерами =Имя=
```

## 7. Ключевые ошибки которых НУЖНО избегать

### ❌ Ошибка #1: ГМ использует маркеры в ответе
```
НЕПРАВИЛЬНО:
"Ты входишь в =Академия_Рендала=. =Лира= встречает тебя."

ПРАВИЛЬНО:
"Ты входишь в Академию Рендала. Лира встречает тебя."
```

### ❌ Ошибка #2: Пустые или бесполезные синопсисы
```
НЕПРАВИЛЬНО:
"synopsis": "студентка"
"synopsis": ""

ПРАВИЛЬНО:
"synopsis": "миниатюрная девушка-лиса, студентка =Академия_Рендала=, флиртует с =Пол="
```

### ❌ Ошибка #3: Связи без контекста
```
НЕПРАВИЛЬНО:
"links": {"Пол": "знает"}

ПРАВИЛЬНО:
"links": {"Пол": "флиртует, хочет потренироваться вместе, интересуется его оружием"}
```

### ❌ Ошибка #4: Односторонние связи
```
НЕПРАВИЛЬНО:
Кири.links["Пол"] = "флиртует"
// Но Пол.links НЕ содержит Кири!

ПРАВИЛЬНО:
Кири.links["Пол"] = "флиртует с =Пол="
Пол.links["Кири"] = "студентка академии, миниатюрная озорная девушка-лисичка, флиртует с ним"
```

## 8. Инвентарь и кванты предметов

### МЕХАНИКА:

**Инвентарь похож на список синопсисов:**
```json
{
  "inventory": {
    "Меч_Катана_Призванная": "+20 атака, можно призывать =Магией_Призыва=",
    "Пистолет_Desert_Eagle": "9 патронов, урон 70",
    "Гранаты_Газовые": "3 штуки, ослепление =Газ_CR="
  }
}
```

**ГМ видит инвентарь:**
- Ключ - имя предмета (ID кванта)
- Значение - краткие характеристики
- **ГМ может запросить любой предмет как квант**

**Quantizer создает кванты для предметов:**
```json
{
  "id": "Меч_Катана_Призванная",
  "type": "item",
  "synopsis": "катана =Пол=, призывается =Магией_Призыва=, урон +20",
  "body": {
    "reference": "Занпакто из Блич, но катана",
    "type": "оружие ближнего боя",
    "damage": "+20 к атаке",
    "ability": "можно призывать и отзывать магией",
    "origin": "получена при =Создание_Персонажа="
  },
  "links": {
    "Пол": "основное оружие",
    "Магия_Призыва": "используется для призыва"
  }
}
```

**Когда создавать кванты для предметов:**
- ✅ Уникальные/магические предметы
- ✅ Предметы с историей или особенностями
- ✅ Предметы важные для сюжета
- ❌ Обычные расходники (если не важны)
