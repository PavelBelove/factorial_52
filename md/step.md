# Принцип работы системы предиктивно-ассоциативной памяти

## Формальное описание компонентов и цикла одного хода

Документ предназначен для разработчиков и LLM-агентов. Он описывает **как именно работает система памяти**, какие компоненты в ней существуют, как они взаимодействуют в течение одного хода диалога и **какие действия каждый компонент принципиально не выполняет**.

Цель архитектуры — обеспечить стабильную долгосрочную память без роста контекста, без векторных представлений и без деградации качества генерации.

---

## 1. Общая модель

Система разделена на:

* **агентов** (LLM с разными ролями);
* **менеджеров** (детерминированные сервисы);
* **хранилище квантов** (семантическая память).

Диалог развивается ходами. Каждый ход — это атомарный цикл, который:

* не зависит от общей длины истории;
* использует только локально релевантную память;
* может выполняться бесконечно долго.

---

## 2. Основные сущности

### 2.1. Квант памяти

Квант — атомарная единица семантической памяти. Он описывает **одну сущность или состояние**, которое может быть упомянуто и переиспользовано.

Пример:

```json5
{
  "id": "Маша",
  "type": "npc",
  "created_at": "turn_12",
  "updated_at": "turn_18",
  "body": {
    "reference": "Хината Хьюго из Наруто",
    "notes": "тихая, наблюдательная",
    "family": "больная мать"
  },
  "links": {
    "Таверна_Атарикс": "раньше работала официанткой",
    "Ремесленный_квартал": "живет неподалеку"
  }
}
```

Свойства:

* `body` — свободная структура, определяемая квантователем;
* `links` — семантические, читаемые связи;
* время указывается **в ходах диалога**, а не в реальных датах.

---

## 3. Компоненты системы

### 3.1. Главный агент (ГМ / ИИ-компаньон)

**Назначение:** вести диалог и прогнозировать следующий шаг.

**Делает:**

* читает подготовленный контекст;
* генерирует ответ пользователю;
* формирует предиктивный запрос квантов.

**Не делает:**

* не создаёт и не редактирует кванты;
* не управляет памятью;
* не анализирует историю целиком.

#### Формат ответа главного агента

```json5
{
  "reply": "Ответ пользователю",
  "quants": ["Маша", "Таверна_Атарикс"]
}
```

`quants` — это **прогноз релевантных сущностей для следующего хода**, а не запрос данных напрямую.

---

### 3.2. Менеджер памяти

**Назначение:** детерминированная работа с базой квантов.

**Делает:**

* получает список имён квантов;
* извлекает соответствующие объекты;
* подтягивает локальные связи ограниченной глубины;
* возвращает компактный семантический фрагмент.

**Не делает:**

* не ищет «похожие» кванты;
* не использует веса, эмбеддинги или ранжирование;
* не интерпретирует смысл.

---

### 3.3. Контекст-менеджер

**Назначение:** сбор оптимального контекста для следующего хода.

**Работает асинхронно**, пока пользователь читает и пишет ответ.

**Собирает:**

* системный промпт;
* актуальное самари;
* 4–7 последних сырых ходов;
* активированные кванты;
* данные от модулей расширения (игровые правила, статы и т.д.).

**Не делает:**

* не решает, что важно;
* не изменяет память;
* не вызывает LLM.

---

### 3.4. Агент-квантователь

**Назначение:** консолидация и коррекция памяти.

Вызывается **раз в 3–4 хода**.

**Получает:**

* текущее самари;
* последние сырые ходы;
* список активированных квантов.

**Возвращает:** команды изменений в текстовом JSON.

Пример инъекции:

```json5
{
  "inject": {
    "id": "Маша",
    "body": {
      "family": "уехала ухаживать за больной матерью"
    },
    "links": {
      "Таверна_Атарикс": "больше не работает"
    }
  }
}
```

**Квантователь:**

* может создавать новые кванты;
* может править или удалять части существующих;
* не переписывает квант целиком без необходимости.

**Не делает:**

* не участвует в диалоге;
* не влияет на стиль;
* не выбирает активные кванты.

---

### 3.5. Менеджер квантов

**Назначение:** применение изменений к базе.

**Делает:**

* применяет инъекции;
* обновляет `updated_at`;
* сохраняет историю изменений.

**Не делает:**

* не принимает решений;
* не интерпретирует смысл команд.

---

### 3.6. Агент-суммаризатор

Вызывается, когда накапливается 7 сырых ходов.

#### Режим 1: инкрементальный

Используется, если длина самари < 20 000 символов.

**Получает:**

* последние сырые ходы;
* предыдущее дополнение самари.

**Результат:** дописывает новое самари к существующему.

#### Режим 2: полная просушка

Используется при превышении порога.

**Получает:**

* всё текущее самари;
* последние сырые ходы.

**Результат:**

* переписывает самари целиком;
* старые события «просушиваются»;
* имена квантов сохраняются как якоря (например `=Маша=`).

**Суммаризатор не:**

* оценивает события;
* изменяет кванты;
* делает выводы.

---

## 4. Полный цикл одного хода

1. Пользователь отправляет сообщение.
2. Главный агент получает подготовленный контекст.
3. Главный агент отвечает и указывает `quants`.
4. Менеджер памяти подготавливает семантическое окно.
5. Контекст-менеджер собирает контекст следующего хода.
6. При необходимости вызываются квантователь и суммаризатор.
7. Система готова к следующему сообщению.

Контекст модели при этом:

* не растёт;
* всегда релевантен;
* отражает текущую ситуацию.

---

## 5. Причины архитектурных решений

* отказ от векторов устраняет шум и дорогую переиндексацию;
* предиктивный запрос памяти делает агента интенциональным;
* разделение ролей предотвращает деградацию качества;
* асинхронная обработка снижает стоимость инференса.

---

## 6. Итог

Система памяти функционирует как **семантический контур внимания**, а не как хранилище данных. Она позволяет LLM:

* существовать в длинных диалогах;
* развивать мир и характер;
* возвращаться к прошлому без потери связности.

Документ описывает полностью достаточный контекст для реализации системы без обращения к дополнительным источникам.
