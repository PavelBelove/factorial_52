# Вопросы и улучшения промптов PlexMem

## Вопросы для уточнения

### 1. Детализация создания персонажа

**Вопрос**: Насколько детальным должно быть создание персонажа?

**Варианты**:
- **Минимальный**: Только имя, начальные характеристики автоматически
- **Базовый**: Имя + выбор внешности из вариантов
- **Подробный**: Имя + внешность + предыстория + особенности
- **Полный**: Всё вышеперечисленное + выбор стартовых навыков/предметов

**Текущий вариант в промптах**: Базовый-Подробный
// Настолько, насколько удобно пользователю. Он может описать подробно или пару деталей. ГМ как опцию предлагает допридумать персонажа в деталях, как только пользователь скажет что персонаж готов - начинаем игру. Квант может и в процессе добавляться деталями, так что это не критично.
**Предложение**: Можно добавить уровни детализации в CharacterCreation:
```json
"creation_modes": {
  "quick": "Быстрое создание - только имя",
  "standard": "Стандартное - имя, внешность, предыстория",
  "detailed": "Детальное - всё + выбор особенностей"
}
```

### 2. Статы и игровая механика

**Вопрос**: Насколько жёсткая система характеристик?

**Варианты**:
- **Жёсткая**: Чёткие HP/мана/статы, механика бросков, строгий учёт
- **Мягкая**: Относительные описания ("ты устал", "мана на исходе")
- **Гибридная**: Есть статы, но GM использует их творчески

**Текущий вариант**: Гибридная (статы есть, но GM их интерпретирует)

**Предложение**: Добавить в gm_system.md раздел:
```markdown
// преждевременно. Система механик разработана, но будет добавляться после тестов памяти, сейчас это не важно. аналогично и с механикой - пока отлаживаем память, потом добавим.
### Механика vs Нарратив

Баланс между игровой механикой и повествованием:
- Статы отслеживай, но не зацикливайся на точности
- Критичные моменты (смертельная опасность) - учитывай HP строго
- Обычные ситуации - фокус на истории, а не цифрах
- Мана важна для способностей призыва
```

### 3. Активация квантов - точность vs гибкость

**Вопрос**: Как строго совпадают названия квантов?

**Проблема**: GM запрашивает "Лира", но квант называется "Гладиаторша_Лира"

**Варианты**:
- **Точное совпадение**: GM должен знать точные имена (требует обучения)
- **Fuzzy matching**: Система находит похожие ("Лира" → "Гладиаторша_Лира")
- **Алиасы**: У квантов есть список альтернативных имён

**Текущее состояние**: Точное совпадение (вызывает ошибки)

**Предложение**: 
1. Краткосрочно: В промптах указать GM использовать полные имена квантов
2. Долгосрочно: Реализовать fuzzy matching в MemoryManager
3. Оптимально: Система алиасов в структуре кванта
// Точно. максимум фуззи поиск, чтобы Лира и лира и Лиры выдали один квант. И ГМ в промпте должен это понимать. Либо =название кванта= в самари, либо точное название активного, либо точное название семантической ссылки внутри кванта.

### 4. Количество стартовых квантов

**Вопрос**: 10 стартовых квантов достаточно?

**Текущие**: CharacterCreation + 9 базовых квантов мира

**Варианты**:
- **Минимум (5-7)**: Только самое необходимое
- **Стандарт (10-15)**: Базовое описание мира
- **Расширенный (30-50)**: Детальный мир с NPC, локациями, квестами

**Предложение**: Создать несколько уровней детализации:
- `data/initial_quants_minimal.json` - 5 квантов
- `data/initial_quants_standard.json` - 10 квантов (текущий)
- `data/initial_quants_rich.json` - 30-50 квантов для готового мира

### 6. Формат связей между квантами

**Вопрос**: Насколько структурированными должны быть связи?

**Текущий формат**:
```json
"links": {
  "Квант": "произвольное описание связи"
}
```

**Альтернативы**:
```json
// Вариант 1: Типизированные связи
"links": {
  "Лира": {"type": "companion", "description": "спутница"}
}

// Вариант 2: Семантические роли
"links": {
  "Лира": {"relation": "COMPANION_OF", "reciprocal": "TRAVELS_WITH"}
}
```
// Пока - произвольное описание. Нет четких правил какие кванты могут возникнуть, к какой категории их отнести и какие именно связи, семантика даст гибкость и понимание контекстной связи.
**Предложение**: Оставить текущий (простой) для MVP, но можно расширить позже

### 7. Триггер Quantizer

**Вопрос**: Каждые 7 ходов оптимально?

**Проблема**: На 7 ходу может быть длинный диалог без новых квантов

**Варианты**:
- **Фиксированный** (7 ходов): Предсказуемо, но не всегда нужно
- **Адаптивный**: Срабатывает при "плотности" новой информации
- **Гибридный**: Минимум 7 ходов, но может раньше если много нового

**Предложение**: Добавить эвристику:
```python
def should_trigger_quantizer(turns_since_last, new_entities_mentioned):
    if turns_since_last >= 10:  # Maximum interval
        return True
    if turns_since_last >= 5 and new_entities_mentioned > 3:
        return True
    return False
```
// Не стоит, ГМ получает "сырые" ходы с пполными "новостями", не обновленные кванты не проблема. Если не успели обновиться - пусть получит 8 а потом 9 сырых ходов, как только обновились - скидываем до 4-х.

### 8. Summarizer - режимы

**Вопрос**: Порог 2000 символов для переключения append→rewrite оптимален?

**Текущая логика**:
- < 2000 символов: append (добавление)
- >= 2000 символов: rewrite (переписывание)

**Проблема**: 2000 символов может быть слишком рано или поздно

**Предложение**: Сделать настраиваемым в config:
```python
SUMMARIZER_APPEND_THRESHOLD = 2000  # символов
SUMMARIZER_MAX_LENGTH = 5000  # максимальная длина саммари
```
// Согласен, стоит вывести в конфиг вообще все переменные - кол-во символов, мин/макс запрашиваемых квантов, сколько ходов в сырой памяти для запуска суммаризатора и квантователя. и сколько остается после их работы и т.д.

### 9. Эмоциональный слой

**Вопрос**: Нужен ли отдельный модуль для эмоций агента?

**В концепт-доке упоминается**: Эмоциональный/субъективный слой как отдельный модуль

**Текущее состояние**: Не реализовано

**Варианты**:
- **Без эмоций**: Нейтральный GM
- **В промпте**: GM описывает эмоции NPC естественно в тексте
- **Отдельный модуль**: Специальные кванты для эмоций/отношений

**Предложение**: Для MVP достаточно "В промпте", но можно добавить:
```json
// Специальный тип кванта
{
  "id": "Отношения_Лира_Character",
  "type": "relationship",
  "body": {
    "from": "Лира",
    "to": "Character",
    "affection": 7,  // 0-10
    "trust": 8,
    "notes": "восхищена силой, благодарна за свободу"
  }
}
```
// Не нужен. будет 2 разных агента, сейчас цель отладить память и бота, после ГМ добавим блок с игровыми правилами, а ИИ напарнику - эмоциональный, но приоритет в памяти.
