# Agent Debug Logging

## Описание

Система логирования для отладки агентов PlexMem. Записывает полный контекст и ответ каждого агента в отдельные файлы.

## Как работает

При каждом вызове агента система сохраняет:
1. **Контекст (Input)** - все сообщения, отправленные в LLM (system prompt + user messages)
2. **Ответ (Output)** - полный ответ от агента в сыром виде

Каждый новый вызов **перезаписывает** предыдущий лог - хранится только последнее выполнение.

## Файлы логов

Логи сохраняются в `logs/agents/`:

```
logs/agents/
├── gm_last.log                  # Последний вызов Game Master
├── quantizer_last.log           # Последний вызов Quantizer
├── summarizer_append_last.log   # Последний Summarizer (append mode)
├── summarizer_rewrite_last.log  # Последний Summarizer (rewrite mode)
└── translator_last.log          # Последний вызов Translator
```

## Формат лога

```
================================================================================
AGENT: GM
TIMESTAMP: 2026-01-24T15:32:10.123456
SESSION: 42
TURN: 15
================================================================================

CONTEXT (Input to LLM):
================================================================================

[Message 1] Role: system
--------------------------------------------------------------------------------
You are a Game Master...

[Message 2] Role: user
--------------------------------------------------------------------------------
Summary:
The player entered the tavern...

Active Quants:
...

================================================================================

RESPONSE (Output from LLM):
================================================================================
{
  "narrative": "Ты входишь в таверну...",
  "response_data": {...},
  "quant_requests": [...]
}

================================================================================
END OF LOG
================================================================================
```

## Включение/выключение

Логирование работает **только** когда `settings.debug = True` в `core/config.py`:

```python
# Application Settings
debug: bool = True  # Agent logging enabled
```

В продакшене установите `debug = False` - логирование будет отключено, никакие файлы не будут записываться.

## Применение для отладки

### 1. Проверить что получает GM
```bash
cat logs/agents/gm_last.log
```

### 2. Увидеть какие команды создал Quantizer
```bash
cat logs/agents/quantizer_last.log | grep -A 50 "RESPONSE"
```

### 3. Проверить работу Translator
```bash
cat logs/agents/translator_last.log
```

### 4. Сравнить два режима Summarizer
```bash
# Режим append
cat logs/agents/summarizer_append_last.log

# Режим rewrite (полная переписка)
cat logs/agents/summarizer_rewrite_last.log
```

## Особенности

- **Безопасность**: Если запись не удалась, ошибка игнорируется - игра не ломается
- **Производительность**: Minimal overhead - запись происходит синхронно, но только один файл
- **Размер**: Последний вызов обычно 10-50 KB в зависимости от контекста
- **История**: Не хранится - всегда только последний вызов для экономии места

## Примеры использования

### Отладка: почему GM не запросил нужный квант?

1. Делаете ход в игре
2. Открываете `logs/agents/gm_last.log`
3. Ищете секцию "Synopsis" в контексте
4. Проверяете - был ли нужный квант в списке доступных
5. Смотрите в RESPONSE - какие кванты запросил GM

### Отладка: почему Quantizer не создал квант?

1. Открываете `logs/agents/quantizer_last.log`
2. Смотрите контекст - видел ли Quantizer нужную информацию
3. Смотрите RESPONSE - какие команды он вернул
4. Проверяете нет ли ошибок валидации

### Отладка: Translator сжимает слишком агрессивно?

1. Открываете `logs/agents/translator_last.log`
2. Видите оригинальный русский текст в контексте
3. Видите JSON ответ
4. Сравниваете - что потерялось при переводе

## Отключение для production

В `.env` или `core/config.py`:

```python
debug = False
```

Все вызовы `log_agent_call()` будут мгновенно возвращать `None` без записи файлов.
