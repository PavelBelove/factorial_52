## Анализ: Агент-переводчик

### Концепция
После каждого хода переводить сырые ходы (player + GM) с русского на английский для сохранения в контекст.

### Расчёты

**Допущения:**
- Средний ход: ~500 токенов (русский)
- После перевода: ~375 токенов (английский, -25%)
- В контексте: 5 сырых ходов одновременно
- Каждый ход используется в контексте ~3 раза

**Стоимость перевода одного хода:**

| Модель переводчика | Стоимость/ход | Break-even |
|-------------------|---------------|------------|
| GPT-4o-mini | $0.000300 | 1.4 использования |
| DeepSeek 3.2 | $0.000175 | 0.8 использований |
| Grok Fast | $0.000119 | 0.6 использований |

**Чистая выгода за сессию (20 ходов):**

| GM Model | Translator | Net Savings | Прибыльность |
|----------|-----------|-------------|--------------|
| DeepSeek 3.2 | GPT-4o-mini | $0.0069 | ✅ |
| DeepSeek 3.2 | DeepSeek 3.2 | $0.0094 | ✅ |

### ⚠️ Недостатки агента-переводчика
1. Добавляет латентность (~1-2s на ход)
2. Усложняет архитектуру (ещё один агент)
3. Может терять нюансы при переводе
4. Нужен мониторинг качества перевода

## 💡 Рекомендации

### 2. JSON-компрессия сырых ходов (Рекомендуется)
**Концепция:**
Вместо полного текста сохранять сырые ходы в компактном JSON:

```json
{
  "turn": 15,
  "player": "Иду в гильдию, сдаю квест",
  "gm_summary": "Сдал квест в гильдии, получил 350 золотых",
  "changes": {
    "gold": +350,
    "xp": {"spades": +1}
  }
}
```

**Преимущества:**
- Экономия 40-60% токенов
- Без LLM (нет дополнительных затрат)
- Простая реализация
- Сохраняет всю важную информацию

**Оценка экономии:**
- На 5 ходах в контексте: ~1250 токенов вместо 2500 → экономия 1250 токенов
- Дополнительная экономия: **$0.0003-0.0004 на ход**

### 3. Агент-переводчик (Опционально)
**Когда имеет смысл:**
- Если контекст растёт (>10 сырых ходов)
- Если используются более дорогие модели ГМ
- Если латентность не критична

**Рекомендуемый переводчик:** DeepSeek 3.2 или Grok Fast (лучший баланс цена/качество)
