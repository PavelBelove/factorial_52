## ❌ Критические проблемы:

### 1. DeepSeek V3.2 НЕ отвечает в JSON формате

**Проблема:**
- GM agent ожидает JSON: `{"reply": "...", "quants": [...]}`
- DeepSeek возвращает **чистый текст** без JSON
- Fallback парсинг извлекает только текст, **теряет список квантов**

**Результат:**
- Ходы 1-2: Кванты запрошены ✅
- Ходы 3-6: Кванты НЕ запрошены ❌
- Ход 7-8: Кванты запрошены ✅
- Ходы 9-19: Кванты НЕ запрошены ❌

**Логи:**
```
17:58:16 - core.agents.gm_agent - WARNING - Could not parse GM response as JSON, using text fallback
17:58:16 - core.orchestrator - INFO - GM response generated. Requested quants: []
```

### 2. Ошибка на 18 ходу

**Что произошло:**
```
18:10:18 - core.llm.openrouter_client - ERROR - Error calling OpenRouter API: All connection attempts failed
18:10:18 - core.agents.gm_agent - ERROR - Error in GM agent: All connection attempts failed
```

**Результат:**
- GM вернул fallback ответ: "Произошла ошибка. Попробуй ещё раз."
- Ход 18 сохранён с этим ответом
- Пользователь попробовал `/undo` и `/retry`

### 3. `/undo` не работает

**Проблема:**
```
18:11:41 - telegram.bot - ERROR - Error in undo command: HTTP Client says - Request timeout error
```

**Причина:**
- `/undo` пытается получить информацию о сессии через API
- Telegram API таймаутит при отправке ответа
- Функционал `/undo` в API не реализован (TODO в коде)

### 4. Retry на 19 ходу загрузил начальные данные

**Логи:**
```
18:11:00 - core.orchestrator - INFO - Turn number: 19
18:11:00 - core.orchestrator - INFO - First turn detected - loading initial quants
18:11:00 - core.orchestrator - INFO - Loading initial data for session 42
```

**Проблема:**
- Система решила что ход 19 - это первый ход
- Загрузила начальные кванты заново
- **НО** сессия не сбросилась - все 19 ходов сохранены

## 🔧 Что нужно исправить:

### Приоритет 1: JSON формат ответа GM

**Решения:**

1. **Добавить `response_format` в API вызов** (для моделей с JSON mode)
   ```python
   response_format={"type": "json_object"}
   ```

2. **Улучшить промпт** - сделать инструкции более явными:
   - "ПЕРВЫЙ СИМВОЛ должен быть `{`"
   - "ПОСЛЕДНИЙ СИМВОЛ должен быть `}`"
   - Больше примеров

3. **Улучшить fallback парсинг** - извлекать кванты из текста:
   - Искать паттерны типа "Запрошенные кванты: X, Y, Z"
   - Извлекать имена из маркеров =Имя=
   - Анализировать текст на упоминания NPC/локаций

### Приоритет 2: Реализовать `/undo`

**Что нужно:**
1. API endpoint для отмены последнего хода
2. Удаление последней записи из `turns`
3. Откат `current_turn` в сессии
4. Удаление квантов, созданных на этом ходу (опционально)

### Приоритет 3: Исправить логику "first turn"

**Проблема:**
- Система проверяет только наличие запрошенных квантов
- Если квантов нет → считает что это первый ход

**Решение:**
- Проверять `current_turn` в сессии
- Загружать начальные данные только если `current_turn == 0`

### Приоритет 4: Улучшить retry логику

**Текущее состояние:**
- Retry работает на уровне Telegram бота
- Повторяет последнее сообщение пользователя
- Создаёт новый ход в БД

**Улучшения:**
- Добавить retry на уровне API (повтор без создания нового хода)
- Сохранять последний успешный ответ GM в памяти
- При ошибке Telegram - повторить отправку без нового запроса к LLM
