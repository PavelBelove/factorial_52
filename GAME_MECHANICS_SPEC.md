# 🎲 План-ТЗ: Игровые механики "Факториал 52!"

## 📋 Общая концепция

Интеграция карточной RPG-механики в PlexMem. Система должна:
- Минимизировать расчеты и инструкции для ГМ
- Предоставлять готовые результаты проверок и боев
- Управлять состоянием персонажа (HP, характеристики, инвентарь)
- Работать прозрачно в фоне, не перегружая контекст

---

## 🏗️ Архитектура

### Выбор: Единый MechanicsManager
**Обоснование**: 
- Проще координация между картами и статами
- Все расчеты в одном месте
- Меньше передачи данных между компонентами
- При росте можно рефакторить на отдельные модули

**Структура**:
```
core/mechanics/
├── __init__.py
├── mechanics_manager.py  # Главный менеджер
├── card_deck.py          # Работа с колодой (внутренний модуль)
├── calculations.py       # Чистые расчеты (внутренний модуль)
└── models.py             # Pydantic модели (Card, Character, etc.)
```

## 📊 Модели данных

### Character (хранится в БД, таблица `characters`)
```python
class Character(BaseModel):
    session_id: int
    
    # Характеристики (4 масти)
    spades: int        # ♠ Пики: сила, ближний бой, воля, запугивание
    hearts: int        # ♥ Червы: магия, магическая защита, мудрость, общение
    diamonds: int      # ♦ Бубны: стойкость, физическая защита, харизма, торговля
    clubs: int         # ♣ Трефы: ловкость, дальний бой, акробатика, скрытность
    
    # Опыт (для автопрокачки, не показывается игроку)
    spades_xp: int = 0    # При 10 XP → +1 к spades, XP обнуляется
    hearts_xp: int = 0
    diamonds_xp: int = 0
    clubs_xp: int = 0
    
    # Состояние
    hp: int
    max_hp: int
    mana: int
    max_mana: int
    gold: int
    
    # Инвентарь (JSON)
    inventory: List[Item]  # До 20 предметов
    equipped: Dict[str, str]  # {"item_id": "Меч_кладенец", ...}
    
    created_at: int
    updated_at: int

# Стартовые значения при создании персонажа:
# mana = hearts × 3
# max_hp = spades + diamonds + clubs
# hp = max_hp
# max_mana = mana

class Item(BaseModel):
    id: str  # "Меч_кладенец"
    type: str  # "weapon", "armor", "accessory", "consumable"
    suit: Optional[str]  # "♠", "♥", "♦", "♣" или None для расходников
    bonus: int  # +25 к характеристике
    description: str
    equipped: bool = False

# Card - это НЕ таблица БД, а класс для работы в коде (одноразовая информация)
class Card:
    rank: int  # 2-10, 11=J, 12=Q, 13=K, 15=A
    suit: str  # "♠", "♥", "♦", "♣"
    color: str  # "red" или "black"
    face_meaning: Optional[str]  # "Валет: сюжетный поворот", "Дама: женская энергия", etc.
    
    def __str__(self) -> str:
        # Формат: "K♠", "8♥", "2♦"
        rank_str = {11: 'J', 12: 'Q', 13: 'K', 15: 'A'}.get(self.rank, str(self.rank))
        return f"{rank_str}{self.suit}"
```

**Важно**: Карты НЕ сохраняются в БД. Каждый ход тянем заново, передаем в контекст, используем и забываем.

## 🎴 Механики

### 1. Раздача карт
**Когда**: Перед каждым ходом (в `TurnOrchestrator.process_turn()`)
**Что**: N=2 пары карт (4 карты) - ВСЕГДА, независимо от того бой или мирное время

**Зачем так много**: Менеджер не знает заранее, что будет в игре:
- 1 пара может использоваться для проверки навыка
- 1 пара может использоваться для боя (игрок атака+защита)
- Та же пара может использоваться врагами (все враги на эту пару)
- Или обе пары в мирное время для сложных проверок

```python
cards_data = mechanics_manager.draw_cards_for_turn(session_id)
# Возвращает:
{
    "cards": [
        {"pair": 1, "cards": ["8♥", "J♠"]},
        {"pair": 2, "cards": ["5♣", "3♦"]}
    ],
    "special_events": ["Валет пик - неожиданный поворот или NPC"]  # Только для мирного времени
}
```

**Важно**: Особые события (фигуры, тузы, двойки) учитываются ТОЛЬКО:
- В мирное время (не в бою)
- Только для карт игрока (не для NPC)

### 2. Расчет порогов сложности
**Когда**: Каждый ход (автоматически)
**Что**: Рассчитываем пороги для всех 4 мастей

```python
thresholds = mechanics_manager.calculate_thresholds(session_id)
# Возвращает:
{
    "average": 52,  # Среднее всех 4 характеристик (для врагов)
    "spades": {"easy": 152, "normal": 202, "hard": 252, "very_hard": 302},    # ♠ Сила, ближний бой, воля
    "hearts": {"easy": 157, "normal": 207, "hard": 257, "very_hard": 307},    # ♥ Магия, защита, общение
    "diamonds": {"easy": 150, "normal": 200, "hard": 250, "very_hard": 300},  # ♦ Стойкость, торговля
    "clubs": {"easy": 145, "normal": 195, "hard": 245, "very_hard": 295}      # ♣ Ловкость, скрытность
}
```

**Важно**: ГМ САМ решает какую масть использовать:
- Взломать сейф → ♣ (ловкость)
- Убедить стражника → ♥ (общение/магия)
- Сломать дверь → ♠ (сила)
- Торговаться → ♦ (харизма/торговля)

### 3. Расчет проверок (вне боя)
**Когда**: ВСЕГДА, перед каждым ходом
**Что**: Считаем результаты для ВСЕХ возможных проверок по всем мастям и обеим парам

**Важно**: Менеджер не знает что будет нужно, поэтому считает все заранее. ГМ просто выбирает нужный результат.

```python
checks = mechanics_manager.calculate_all_checks(session_id, cards_data)
# Возвращает:
{
    "pair_1": {
        "cards": ["8♥", "J♠"],  # (8 + 11) = 19
        "base_roll": 190,  # 19 × 10
        "color_bonus": 0,  # Разные цвета
        "suit_bonus": 0,   # Разные масти
        
        "spades": {
            "total": 190 + 45 = 235,  # base + характеристика[♠]
            "vs_easy": {"threshold": 152, "success": True, "margin": 83},
            "vs_normal": {"threshold": 202, "success": True, "margin": 33},
            "vs_hard": {"threshold": 252, "success": False, "margin": -17},
            "vs_very_hard": {"threshold": 302, "success": False, "margin": -67}
        },
        "hearts": {
            "total": 190 + 50 = 240,
            "vs_easy": {...}, "vs_normal": {...}, ...
        },
        "diamonds": {...},
        "clubs": {...}
    },
    "pair_2": {
        "cards": ["5♣", "3♦"],  # (5 + 3) = 8
        "base_roll": 80,
        "color_bonus": 10,  # Обе красные!
        "suit_bonus": 0,
        
        "spades": {"total": 90 + 45 = 135, ...},
        "hearts": {"total": 90 + 50 = 140, ...},
        ...
    },
    
    "special_events": ["Валет пик - неожиданный поворот или NPC"]
}
```

**Формула проверки**:
```
Результат = (номинал1 + номинал2) × 10 + характеристика_масти + бонус_за_цвет + бонус_за_масть

Бонусы:
- Одинаковый цвет: +10 (красные) / -10 (черные)
- Одинаковая масть: +20 (красные) / -20 (черные)
```

### 4. Расчет боя
**Когда**: ВСЕГДА (на всякий случай)
**Что**: Считаем ВСЕ возможные действия для игрока с одной парой карт

**Важно**: 
- Игрок НЕ видит карты перед выбором действия
- Считаем все варианты: атака ближняя/дальняя/магическая, защита физ/маг
- Можно делать 2 действия за ход (комбо) - используются те же 2 карты для обоих
- Особые события (фигуры, тузы) НЕ учитываются в бою

```python
combat = mechanics_manager.calculate_all_combat_options(session_id, cards_data)
# Возвращает для ОДНОЙ пары карт (всегда используем ОБЕ карты):
{
    "pair_1": {
        "cards": ["K♠", "8♣"],  # 13 и 8, обе черные
        
        # ВАЖНО: Всегда используем ОБЕ карты для действия
        # Бонус ИЛИ за масть (+20) ИЛИ за цвет (+10)
        
        "melee_attack": {       # ♠ Ближняя атака
            "card1_bonus": 20,  # K♠: +20 за совпадение масти
            "card2_bonus": 10,  # 8♣: +10 за цвет (черные)
            "total": 240 + spades  # (130+20) + (80+10) + spades
        },
        "ranged_attack": {      # ♣ Дальняя атака
            "card1_bonus": 10,  # K♠: +10 за цвет
            "card2_bonus": 20,  # 8♣: +20 за совпадение масти
            "total": 240 + clubs
        },
        "magic_attack": {       # ♥ Магическая атака
            "card1_bonus": 0,   # Черные карты, масть не совпадает
            "card2_bonus": 0,
            "total": 210 + hearts  # 130 + 80 + hearts
        },
        "physical_defense": {   # ♦ Физическая защита
            "card1_bonus": 0,
            "card2_bonus": 0,
            "total": 210 + diamonds
        },
        "magic_defense": {      # ♥ Магическая защита
            "card1_bonus": 0,
            "card2_bonus": 0,
            "total": 210 + hearts
        },
        
        # Комбо (2 действия за ход - используем те же карты для обоих)
        "melee_and_phys_def": {
            "attack": 240 + spades,    # K♠(+20) + 8♣(+10)
            "defense": 210 + diamonds  # K♠ + 8♣ без бонусов
        },
        "ranged_and_phys_def": {
            "attack": 240 + clubs,     # K♠(+10) + 8♣(+20)
            "defense": 210 + diamonds
        },
        "magic_and_phys_def": {
            "magic": 210 + hearts,
            "defense": 210 + diamonds
        }
    },
    
    # Для врага используем среднее или уровень опасности
    "enemy_simple": {
        "cards": ["7♥", "5♦"],
        "danger_level": 30,  # ГМ назначает (гоблин=20, орк=40, дракон=100)
        "attack": 120 + 30 = 150,   # (70 + 50) + danger
        "defense": 120 + 30 = 150   # Те же карты для защиты
    }
}
```

**Формула боя**:
```
Значение карты = номинал × 10

ВАЖНО: Бонус ИЛИ за масть (+20) ИЛИ за цвет (+10), НЕ складываются!
Всегда используем ОБЕ карты, каждая получает свой бонус.

Приоритет бонусов:
1. Если масть совпадает с типом действия → +20
2. Иначе, если обе карты одного цвета → +10
3. Иначе → без бонуса

Итоговое значение = (карта1 + бонус1) + (карта2 + бонус2) + характеристика

Примеры с картами K♠ и 8♣ (обе черные):

1. Атака мечом (♠):
   - K♠: 130 + 20 (масть ♠ совпадает) = 150
   - 8♣: 80 + 10 (цвет черный) = 90
   - Итого: 150 + 90 + spades = 240 + spades

2. Атака на расстоянии (♣):
   - K♠: 130 + 10 (цвет черный) = 140
   - 8♣: 80 + 20 (масть ♣ совпадает) = 100
   - Итого: 140 + 100 + clubs = 240 + clubs

3. Защита щитом (♦) или магией (♥):
   - K♠: 130 + 0 (черная карта, масть не совпадает) = 130
   - 8♣: 80 + 0 = 80
   - Итого: 130 + 80 + diamonds = 210 + diamonds

4. Комбо (атака мечом + защита щитом):
   Используем ту же пару K♠ и 8♣ для ОБОИХ действий:
   
   Атака (♠): 240 + spades (например, spades=50 → 290)
   Защита (♦): 210 + diamonds (например, diamonds=45 → 255)
   
   Игрок наносит 290 урона И защищается на 255 одновременно!
```

### 5. Применение изменений от ГМ
**Когда**: После ответа ГМ
**Что**: Парсим JSON и обновляем состояние персонажа

**Важно**: ГМ НЕ запрашивает проверки или бой - все расчеты уже сделаны. Он только применяет изменения.

```python
# ГМ возвращает в дополнительном поле response_data:
{
    "hp": -15,  # Относительное изменение (-урон или +лечение)
    "mana": -10,
    "stats": {
        "spades": 1,    # +1 за успешное использование силы
        "hearts": 10    # +10 если персонаж обучился у мастера
    },
    "inventory": {
        "add": [
            {"id": "Меч_кладенец", "type": "weapon", "suit": "♠", 
             "bonus": 25, "description": "Легендарное оружие древних"}
        ],
        "remove": ["Зелье_лечения"]
    },
    "equip": ["Меч_кладенец"],    # Надеть предмет
    "unequip": ["Старый_меч"],    # Снять предмет
    "gold": 100  # Получено золота (+) или потрачено (-)
}

mechanics_manager.apply_gm_changes(session_id, gm_response_data)
```

**Примечания**: 
- Квантователь автоматически создаст квант для "Меч_кладенец" если это значимый предмет (не расходник)
- Расходники (зелья, еда) и типичные враги (гоблины, скелеты) - просто в инвентаре, без квантов
- Уникальные предметы ("зелье из слез единорога") и именованные враги - квантователь создаст кванты

### 7. Автоматическая прокачка
**Когда**: После каждой успешной проверки навыка
**Что**: Система автоматически добавляет опыт и повышает характеристики

```python
# При успешной проверке (например, магии):
character.hearts_xp += 1

if character.hearts_xp >= 10:
    character.hearts += 1
    character.hearts_xp = 0
    character.max_hp += 1    # При любой прокачке +1 HP
    character.max_mana += 1  # При любой прокачке +1 мана
    # Игроку НЕ сообщается явно, просто видит изменения в stats

# Это происходит автоматически, ГМ ничего не делает
```

**Важно**: Игроку НЕ сообщается "Вы получили опыт" или "Характеристика повысилась". Он просто видит новые значения в следующем ходу.

### 6. Создание персонажа
**Когда**: При команде `/start` (первый ход новой игры)
**Что**: Генерируем начальные характеристики с помощью 5 случайных карт

```python
# При создании новой игры (session)
creation_data = mechanics_manager.create_character(session_id)
# Возвращает:
{
    "cards": ["7♠", "Q♥", "5♦", "K♣", "3♥"],  # 5 случайных карт
    "instructions": """
Вытянуты 5 карт для создания персонажа:
1. 7♠ (35 очков, +10 если назначить на ♠ Силу)
2. Q♥ (60 очков, +10 если назначить на ♥ Магию)
3. 5♦ (25 очков, +10 если назначить на ♦ Стойкость)
4. K♣ (65 очков, +10 если назначить на ♣ Ловкость)
5. 3♥ (15 очков, ХУДШАЯ - не учитывается)

Ты можешь:
- Распределить карты по характеристикам самостоятельно
- Попросить меня распределить оптимально

Характеристики:
♠ Сила: ближний бой, сила, воля, запугивание
♥ Магия: магическая защита, колдовство, мудрость, общение
♦ Стойкость: физическая защита, выносливость, харизма, торговля
♣ Ловкость: дальний бой, акробатика, меткость, скрытность
"""
}
```

**Процесс**:
1. Система тянет 5 карт
2. Добавляет их в контекст для ГМ
3. ГМ объясняет игроку правила распределения
4. Игрок отвечает (например: "силу на 7♠, магию на Q♥..." или "распредели оптимально")
5. На следующем ходу ГМ возвращает в `response_data`:
```json
{
    "create_character": {
        "spades": 45,    // 7♠ = 7×5 + 10 = 45
        "hearts": 70,    // Q♥ = 12×5 + 10 = 70
        "diamonds": 25,  // 5♦ = 5×5 (без бонуса)
        "clubs": 75      // K♣ = 13×5 + 10 = 75
    }
}
```
6. Система создает персонажа в БД

**Формула расчета характеристики**:
```
Значение = номинал × 5 + (10 если масть совпадает)

Валет = 11, Дама = 12, Король = 13, Туз = 15
```

## 🎯 Правила расчетов

### Проверки (вне боя)
```
Базовый бросок = (номинал1 + номинал2) × 10

Бонусы:
- Одинаковый цвет: +10 (красные) / -10 (черные)
- Одинаковая масть: +20 (красные) / -20 (черные)

Итоговый результат = базовый_бросок + бонусы + характеристика_масти

Пороги сложности (от базового + среднее_характеристик):
- Легко: 100 + среднее
- Средне: 150 + среднее
- Сложно: 200 + среднее
- Очень сложно: 250 + среднее

Пример: Персонаж (♣ 60, среднее 50) прыгает через ущелье
Карты: 8♥ + K♠
Бросок: (8 + 13) × 10 = 210
Бонусы: 0 (разные цвета и масти)
Результат: 210 + 60 = 270
Порог (сложно): 200 + 50 = 250
Успех! (270 > 250)
```

### Бой
```
Значение карты = номинал × 10

ВАЖНО: Всегда используем ОБЕ карты!
Бонус для каждой карты ИЛИ +20 (масть) ИЛИ +10 (цвет), НЕ складываются!

Приоритет бонусов для каждой карты:
1. Если масть совпадает с типом действия → +20
   - ♠ Пики: ближняя атака
   - ♥ Червы: магическая защита  
   - ♦ Бубны: физическая защита
   - ♣ Трефы: дальняя атака
2. Иначе, если обе карты одного цвета → +10
3. Иначе → без бонуса

Итоговое значение = (карта1 + бонус1) + (карта2 + бонус2) + характеристика
Урон = атака - защита

Пример 1: Атака мечом (♠), карты K♠ и 8♣ (обе черные)
- K♠: 130 + 20 (масть) = 150
- 8♣: 80 + 10 (цвет) = 90
- Итого: 240 + spades (например, spades=50 → 290)

Пример 2: Дальняя атака (♣), те же карты K♠ и 8♣
- K♠: 130 + 10 (цвет) = 140
- 8♣: 80 + 20 (масть) = 100
- Итого: 240 + clubs

Пример 3: Защита щитом (♦), те же карты
- K♠: 130 + 0 (черная, не совпадает) = 130
- 8♣: 80 + 0 = 80
- Итого: 210 + diamonds
```

### Комбо-действия
```
Можно делать 2 действия за ход, используя обе карты:
- Атака + защита (одна карта на атаку, другая на защиту)
- Комбо-атака (магический выстрел = ♥+♣, складываются обе характеристики)

Ограничение: Если для атаки выпали 2 КРАСНЫЕ карты = провал атаки
(можно только защищаться в этот ход)
```

### Особые события (ТОЛЬКО вне боя, ТОЛЬКО для игрока)
```
Фигуры (влияют на сюжет):
- Валет: Неожиданный поворот, появление NPC
- Дама: Влияние женского персонажа/энергии
- Король: Влияние мужского персонажа/энергии

Критические результаты:
- Два туза (A+A): Божественный успех, невероятная удача
- Две двойки (2+2): Катастрофа, критический провал

В бою фигуры и критические результаты НЕ учитываются!
Для NPC особые события НЕ учитываются!
```

### Инвентарь
```
- Максимум N=20 предметов (конфигурируется)
- Носить можно неограниченно (ГМ решает семантически что подходит)
- Каждый предмет привязан к масти (кроме расходников)
- При надевании/снятии автоматически пересчитываются бонусы
- Квантователь создает карточку только для значимых предметов (не расходники)

Пример:
Меч_кладенец (♠, +25) → spades увеличивается на 25 при надевании
```

### Враги
```
ГМ назначает врагу "уровень опасности" (одно число):
- Гоблин: 20 (слабее персонажа)
- Орк: 40 (примерно равен)
- Дракон: 100 (значительно сильнее)

Это число добавляется ко всем действиям врага.
Квантователь фиксирует врагов для консистентности.
```

```python
def build_context(self, ..., module_data: Optional[Dict] = None):
    messages = []
    
    # ... существующий код ...
    
    # Добавляем игровые механики
    if module_data:
        if "character_creation" in module_data:
            mechanics_section = self._format_character_creation(module_data["character_creation"])
        elif "character" in module_data:

        else:

        if mechanics_section:

                "content": mechanics_section
            })
    
    return messages

def _format_mechanics_for_context(self, module_data: Dict) -> str:
    char = module_data["character"]
    cards = module_data["cards"]
    checks = module_data["checks"]
    combat = module_data["combat"]
    thresh = module_data["thresholds"]
    
    # Форматируем компактно (~300 токенов)
    return f"""# 🎲 Игровые механики

## Персонаж
**HP**: {char['hp']}/{char['max_hp']} | **Мана**: {char['mana']}/{char['max_mana']} | **Золото**: {char['gold']}

**Характеристики** (среднее: {thresh['average']}):
♠ Сила: {char['spades']} | ♥ Магия: {char['hearts']} | ♦ Стойкость: {char['diamonds']} | ♣ Ловкость: {char['clubs']}

## 🎴 Карты (вытянуты случайно, игрок НЕ видит)
Пара 1: {cards['cards'][0]['cards'][0]} + {cards['cards'][0]['cards'][1]}
Пара 2: {cards['cards'][1]['cards'][0]} + {cards['cards'][1]['cards'][1]}

{self._format_special_events(cards['special_events'])}

## 🎯 Готовые расчёты проверок (пара 1)
{self._format_checks_compact(checks['pair_1'], thresh)}

## ⚔️ Готовые расчёты боя (пара 1)
{self._format_combat_compact(combat['pair_1'])}

## 🎒 Инвентарь ({len(char['inventory'])}/20)
{self._format_inventory_compact(char['inventory'], char['equipped'])}

---
**Инструкции**:
1. Ты НЕ делаешь расчеты - все уже посчитано выше
2. Просто выбери нужный результат и опиши сюжетно
3. В `response_data` укажи только изменения (HP, мана, предметы, золото)
4. Особые события (фигуры) используй ТОЛЬКО в мирное время для игрока"""

def _format_checks_compact(self, pair_checks: Dict, thresh: Dict) -> str:
    # Показываем только итоговые значения для каждой масти
    return f"""
♠ Сила: {pair_checks['spades']['total']} vs порог (легко {thresh['spades']['easy']}, сложно {thresh['spades']['hard']})
♥ Магия: {pair_checks['hearts']['total']} vs порог (легко {thresh['hearts']['easy']}, сложно {thresh['hearts']['hard']})
♦ Стойкость: {pair_checks['diamonds']['total']}
♣ Ловкость: {pair_checks['clubs']['total']}
"""

def _format_combat_compact(self, pair_combat: Dict) -> str:
    # Показываем самые сильные варианты атаки и защиты
    return f"""
Лучшая атака: ближняя {pair_combat['melee_attack']['card1']['total']} | дальняя {pair_combat['ranged_attack']['card2']['total']}
Лучшая защита: физ. {pair_combat['physical_defense']['card1']['total']} | маг. {pair_combat['magic_defense']['card1']['total']}
Комбо (атака+защита): доступно
"""
```
