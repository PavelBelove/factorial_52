# Изменения от 2026-01-18

## ✅ Реализовано

### 0. Синопсисы квантов для навигации 🎯
**Проблема:** 
- Квантователь создает дубли ("Лилит", "Лилит_официантка", "Лилит_девушка_кошка")
- Не видит все существующие кванты
- ГМ не понимает какие кванты связаны между собой

**Решение:**
- Добавлено поле `synopsis: Optional[str]` в квант (макс 500 символов)
- Синопсис = краткое описание с маркерами `=ИмяКванта=` для связей
- Пример: `"Официантка в таверне =Золотой_Телец=, город =Архонт="`
- Новый параметр `quants_synopsis_window: int = 30` в config
- Метод `get_recent_quants_synopsis()` - список квантов за последние 30 ходов
- ГМ и Квантователь видят секцию "Доступные кванты (последние обновления)"
- Квантователь ОБЯЗАН проверять список перед созданием нового кванта
- Маркеры `=имя=` помогают ГМ понимать какие кванты можно запросить

**Технические изменения:**
- `QuantDB.synopsis VARCHAR(500)`
- `ContextManager` теперь получает `memory_manager` в конструкторе
- Обновлены промпты ГМ и Квантователя с инструкциями по synopsis
- Миграция: `ALTER TABLE quants ADD COLUMN synopsis VARCHAR(500);`

### 1. Фильтр дубликатов при append
- Добавлен fuzzy-matching для определения повторяющегося контента
- При append проверяется similarity с существующими частями (threshold 85%)
- Дубликаты пропускаются с логированием
- Решает проблему повторов в квантах (например, в Лире)

### 2. Упрощены логи ГМ
- Убран verbose вывод полного контекста в логи
- Теперь логируется только:
  - Количество сообщений
  - Короткий ответ (первые 200 символов)
  - Запрошенные кванты
- Логи стали читаемыми

### 3. Модель изменена на Grok 4.1 Fast
- Все агенты (GM, Quantizer, Summarizer) используют `x-ai/grok-4.1-fast`
- Быстрее чем DeepSeek v3.2
- 128K контекст

### 4. Система алиасов для NPC
**Проблема:** "Дриада из леса" → "Ивушка" (когда представилась)

**Решение:**
- Добавлено поле `aliases` в QuantDB и Quant model
- Новая команда квантователя: `rename_СтароеИмя: "НовоеИмя"`
- Старое имя автоматически добавляется в алиасы
- Fuzzy search работает по ID и всем алиасам
- Пример: `rename_Дриада_из_леса: "Ивушка"` → оба имени работают

### 5. Автоматические backlinks
**Проблема:** Лира ссылается на Зачарованный_лес, но обратной ссылки нет

**Решение:**
- Обновлён промпт квантователя с **критичным правилом**:
  - При создании/обновлении связи A → B ОБЯЗАТЕЛЬНО создавать B → A
- Добавлен пример в промпт:
```json
{
  "append_Лира_links_Зачарованный_лес": "родные места отца",
  "append_Зачарованный_лес_links_Лира": "дочь пропавшего исследователя"
}
```

### 6. Новые типы квантов
- `scene` - сюжетные сцены, отдельные эпизоды
- `promise` - обещания, договорённости, планы "на потом"

## 🎯 Как использовать

### Переименование NPC
Когда безымянный NPC представился:
```json
{
  "rename_Полуэльфийка_из_деревни": "Элара"
}
```
Теперь оба имени будут находить один квант.

### Backlinks
При создании связи:
```json
{
  "append_Лира_links_Зачарованный_лес": "место пропажи отца",
  "append_Зачарованный_лес_links_Лира": "дочь пропавшего исследователя"
}
```

### Новые типы
```json
{
  "create_Встреча_с_герцогом": {
    "type": "scene",
    "body": {"description": "Первая аудиенция у герцога"}
  },
  "create_Вернуться_за_наградой": {
    "type": "promise",
    "body": {"who": "Игрок", "what": "обещал вернуться через неделю"}
  }
}
```

## ⚠️ Миграция БД

**ВАЖНО:** Добавлено новое поле `aliases` в таблицу `quants`.

При первом запуске SQLite автоматически добавит колонку.
Для PostgreSQL потребуется миграция:
```sql
ALTER TABLE quants ADD COLUMN aliases JSON DEFAULT '[]';
```
