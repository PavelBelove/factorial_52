# Система промптов PlexMem

## Структура

### Промпты агентов
- `prompts/gm_system.md` - Промпт для Game Master (главный диалоговый агент)
- `prompts/quantizer_system.md` - Промпт для Quantizer (управление квантами памяти)
- `prompts/summarizer_system.md` - Промпт для Summarizer (сжатие истории)

### Стартовые данные для новой игры
- `data/initial_summary.md` - Начальное саммари с описанием мира
- `data/initial_quants.json` - Стартовые кванты (10 штук)

## Стартовые кванты

### Специальные кванты:

**CharacterCreation** (is_game: false) - КРИТИЧЕСКИЙ квант для начала игры:
- Запрашивается GM только в самом начале
- Содержит инструкции для GM по созданию персонажа
- Содержит инструкции для Quantizer создать Character и Inventory
- После создания персонажа Quantizer УДАЛЯЕТ этот квант // пусть квант остается с единственной ссылкой на Character с пометкой что нужен для создания/изменения персонажа, не запрашивать без прямого запроса. Не будем грузить этим промпты, но если понадобится отредактировать персонажа в процессе ГМ вызовет его снова. Ну и в самом кванте, не в промпте инструкции по его использованию, что видишь это - приоритет, сейчас процесс создания персонажа, как только он создастся и начнется игра - не запрашивай более этот квант. Чтобы не перегружая промпты ГМ и квантователь получали инструкции строго в этот момент.

**Character** (is_game: false) - создаётся Quantizer после создания персонажа:
- Полное описание персонажа игрока
- Имя, раса, класс, внешность, характер, предыстория
- Статы (HP, мана, характеристики)
- Обновляется по ходу игры

**Inventory** (is_game: false) - создаётся Quantizer после создания персонажа:
- Инвентарь и экипировка игрока
- Оружие, доспехи, предметы, деньги
- Обновляется при получении/потере предметов

### Базовые кванты мира (is_game: true):

1. **Олимпия** - описание мира // Лучше сделаем это не квантом. а "первым самари", т.е. на старте мир = самари, ГМ получает полный контекст, самари больше не опция, оно было изначально просто обезличенное.
2. **Драг** - магический спутник персонажа (дракон-татуировка)
3. **Боги_Олимпии** - пантеон богов
4. **Призванные_Герои** - концепция призванных героев
5. **Способность_Призыва** - уникальная способность игрока
6. **Магическая_Система** - как работает магия
7. **Арена** - стартовая локация
8. **Гладиаторы** - концепция гладиаторов
9. **Расы_Олимпии** - расы мира

## Логика работы промптов

### Game Master (GM)

**Главная задача**: Вести диалог и предсказывать нужные кванты

**Ключевые моменты**:
- НЕ использует маркеры =квант= в тексте для игрока (пишет естественно)
- Запрашивает 3-7 квантов для СЛЕДУЮЩЕГО хода
- Не создаёт и не изменяет кванты сам
- В начале игры запрашивает CharacterCreation
- После создания персонажа НИКОГДА не запрашивает CharacterCreation

**Контекст GM**:
1. System prompt (gm_system.md)
2. Summary (если есть)
3. Active quants (запрошенные на прошлом ходу)
4. Recent turns (5-7 последних)
5. Module data (опционально)

### Quantizer

**Главная задача**: Создавать, обновлять и удалять кванты

**Ключевые моменты**:
- Создаёт кванты только для ВАЖНЫХ сущностей
- Использует команды: create_, append_, replace_, delete_
- Создаёт осмысленные связи между квантами
- После создания персонажа: создаёт Character и Inventory, удаляет CharacterCreation
- Срабатывает каждые 7 ходов

**Контекст Quantizer**:
1. System prompt (quantizer_system.md)
2. Summary (если есть)
3. Last 7 turns (сырые ходы)
4. Activated quants (какие кванты были активны)

### Summarizer 
// здесь лучше разделить режимы на 2 отдельных промпта. при добавлении агенту не нужно знать про режим переписывания, при переписывании - вызываем с промптом только для этого.

**Главная задача**: Конденсировать старые ходы в саммари

**Ключевые моменты**:
- Два режима: append (добавление) и rewrite (переписывание)
- Сохраняет ключевые события, персонажей, квесты
- НЕ дублирует информацию из квантов
- Краткость и информативность

**Контекст Summarizer**:
1. System prompt (summarizer_system.md)
2. Current summary (текущее саммари)
3. Turns to summarize (ходы для сжатия)

## Процесс начала новой игры

### 1. Создание сессии
Когда пользователь начинает новую игру:
```python
# Загружаются стартовые данные
summary = load("data/initial_summary.md")
quants = load("data/initial_quants.json")

# Сохраняются в БД для новой сессии
```

### 2. Первый ход
GM получает в контексте:
- System prompt
- Initial summary
- Quants: CharacterCreation, Драг, Олимпия, и др.
- 0 turns (это первый ход)

GM запрашивает: `["CharacterCreation", "Драг", "Олимпия"]`

### 3. Создание персонажа
GM ведёт диалог создания персонажа, следуя инструкциям из CharacterCreation.

### 4. После создания (ход ~3-5)
Quantizer срабатывает (ход 7) и:
```json
{
  "create_Character": {
    "type": "concept",
    "body": {...},
    "is_game": false
  },
  "create_Inventory": {
    "type": "concept",
    "body": {...},
    "is_game": false
  },
  "delete_CharacterCreation": null
}
```

### 5. Дальнейшая игра
GM больше не запрашивает CharacterCreation, но может запрашивать Character и Inventory при необходимости.

## Важные правила

### Для GM:
1. Маркеры =квант= - ТОЛЬКО внутренняя кухня, не показывать игроку
2. CharacterCreation - только в самом начале
3. Запрашивай кванты для СЛЕДУЮЩЕГО хода, а не текущего
4. 3-7 квантов оптимально

### Для Quantizer:
1. НЕ создавай кванты для незначимых элементов (рандомные враги, проходные предметы)
2. Создавай осмысленные связи (не "связан", а "спутница героя")
3. CharacterCreation → Character + Inventory + delete CharacterCreation
4. Обратные связи важны (A→B и B→A)

### Для Summarizer:
1. НЕ дублируй кванты (саммари о событиях, кванты о сущностях)
2. Краткость критична
3. Режим append до 2000 символов, потом rewrite
4. Сохраняй якоря (имена, места, квесты)

## Настройка под свой сеттинг

Чтобы адаптировать под свой мир:

1. Отредактируй `data/initial_summary.md` - опиши свой мир
2. Отредактируй `data/initial_quants.json` - создай свои стартовые кванты
3. Обнови CharacterCreation - процесс создания персонажа
4. Можешь отредактировать `prompts/gm_system.md` - стиль повествования

**Не меняй**:
- Логику работы квантов
- Формат команд Quantizer
- Структуру промптов (можешь дополнять, но не ломай базовую логику)

## Тестирование промптов

После изменения промптов:
1. Проверь начало новой игры (создание персонажа)
2. Проверь работу на 7+ ходах (срабатывание Quantizer)
3. Проверь логи - видишь ли правильные команды
4. Проверь активацию квантов - запрашиваются ли нужные
