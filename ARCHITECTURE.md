# PlexMem - Архитектура системы

## Обзор

PlexMem - система предиктивно-ассоциативной памяти для LLM-агентов. Ключевое отличие от традиционных RAG-систем: вместо реактивного поиска используется **предиктивная активация** памяти.

## Ключевые принципы

1. **Фиксированный контекст**: память не растёт в контексте модели
2. **Предиктивность**: агент запрашивает кванты для *следующего* хода
3. **Семантические связи**: кванты связаны осмысленно, не статистически
4. **Разделение ответственности**: три агента + два менеджера

## Компоненты системы

### 1. Database Layer (`core/database/`)

**DatabaseManager** - абстракция над БД, готовая к миграции с SQLite на PostgreSQL.

Таблицы:
- `users` - пользователи платформы
- `sessions` - сессии диалога
- `quants` - кванты памяти
- `turns` - ходы диалога
- `summaries` - сводки истории

### 2. Managers (`core/managers/`)

#### MemoryManager
Управляет квантами:
- Создание, обновление, удаление
- Парсинг команд от Quantizer
- Fuzzy-поиск квантов по имени
- Обработка инъекций

Формат команд:
```
create_ИмяКванта: {полные данные}
append_ИмяКванта_body_ключ: значение
replace_ИмяКванта_links_Другой: новая_связь
delete_СтарыйКвант: null
```

#### ContextManager
Собирает контекст для хода:
- Системный промпт (модульный)
- Сводка истории
- Активные кванты
- Сырые ходы (4-7 последних)
- Опционально: данные модулей

### 3. Agents (`core/agents/`)

#### GMAgent (Главный агент)
**Функции:**
- Ведение диалога
- Генерация ответа пользователю
- Предиктивный запрос квантов

**НЕ делает:**
- Не создаёт кванты
- Не обращается ко всей БД
- Не управляет памятью

**Формат ответа:**
```json
{
  "reply": "Текст ответа игроку",
  "quants": ["Квант1", "Квант2"]
}
```

#### QuantizerAgent (Квантователь)
**Функции:**
- Анализ диалога
- Создание новых квантов
- Обновление существующих
- Управление связями

**НЕ делает:**
- Не участвует в диалоге
- Не влияет на стиль
- Не выбирает активные кванты

**Контекст:**
- Сводка (краткая)
- Последние 5 ходов
- Активные кванты
- Текущий номер хода

#### SummarizerAgent (Суммаризатор)
**Функции:**
- Конденсация истории
- Сохранение якорей (=квант=)
- Два режима: append / rewrite

**Режимы:**
1. **Append** (< 20000 символов):
   - Получает последние ходы
   - Дописывает к существующей сводке

2. **Rewrite** (>= 20000 символов):
   - Получает всю сводку + недавние ходы
   - Переписывает, "высушивая" старые события

### 4. Orchestrator (`core/orchestrator.py`)

**TurnOrchestrator** - координирует весь цикл хода.

#### Цикл хода:

```
1. Пользователь → сообщение
   ↓
2. Получить активные кванты (из предыдущего хода)
   ↓
3. ContextManager собирает контекст
   ↓
4. GMAgent генерирует ответ + запрос квантов
   ↓
5. Сохранить ход в БД
   ↓
6. Пользователь ← ответ
   ↓
7. (Фоновая задача) Каждые N ходов:
   - Quantizer обновляет кванты
   - Summarizer конденсирует историю
```

**Важно:** квантователь и суммаризатор работают асинхронно, не блокируя ответ пользователю.

### 5. API (`core/api/`)

FastAPI эндпоинты:

#### `POST /sessions`
Создать новую сессию

#### `POST /sessions/{id}/messages`
Отправить сообщение (основной эндпоинт)

#### `GET /sessions/{id}`
Информация о сессии

#### `GET /sessions/{id}/quants`
Все кванты сессии

#### `GET /sessions/{id}/history`
История диалога

### 6. LLM Client (`core/llm/`)

**OpenRouterClient** - обёртка над OpenRouter API.

**Функции:**
- Запросы с полным логированием
- Парсинг JSON из ответов
- Обработка ошибок
- Извлечение JSON из markdown-блоков

**Поддерживает:**
- `chat_completion()` - полный запрос
- `simple_completion()` - текстовый ответ
- `json_completion()` - JSON ответ

## Формат данных

### Квант (Quant)
```json
{
  "id": "Маша",
  "type": "npc",
  "body": {
    "role": "официантка",
    "notes": "тихая, наблюдательная"
  },
  "links": {
    "Таверна Атарикс": "работает официанткой",
    "Ремесленный квартал": "живет неподалеку"
  },
  "created_at": 12,
  "updated_at": 18,
  "is_game": true
}
```

### Turn (Ход)
```python
{
  "turn_number": 5,
  "user_message": "Я захожу в таверну",
  "agent_reply": "Ты входишь...",
  "requested_quants": ["Таверна Атарикс", "Маша"],
  "timestamp": "2024-01-15T10:30:00"
}
```

### Summary (Сводка)
```python
{
  "summary_text": "Игрок прибыл в =Атарикс=. Встретил =Маша=...",
  "turns_start": 1,
  "turns_end": 10,
  "is_full_rewrite": false
}
```

## Конфигурация

### Основные параметры (`core/config.py`)

```python
MAX_QUANTS_PER_REQUEST = 10      # Макс квантов в запросе
RAW_TURNS_MIN = 4                # Мин сырых ходов
RAW_TURNS_MAX = 7                # Макс сырых ходов
SUMMARY_SIZE_THRESHOLD = 20000   # Порог для rewrite
QUANTIZER_TRIGGER_TURNS = 7      # Частота вызова квантователя
```

## Потоки данных

### Прямой поток (пользователь → ответ)
```
User Message
    ↓
[Get Active Quants]
    ↓
[Build Context]
    ↓
[GM Agent]
    ↓
[Save Turn]
    ↓
Reply to User
```

### Фоновый поток (обновление памяти)
```
(Async, every N turns)
    ↓
[Get Recent History]
    ↓
┌─────────────┬──────────────┐
│  Quantizer  │ Summarizer   │
└─────────────┴──────────────┘
    ↓               ↓
[Update Quants] [Update Summary]
```

### Текущее (MVP)

- Асинхронная обработка

### Будущее

## Расширяемость

### Модули
Система поддерживает модули через `module_data` в контексте:

```python
module_data = {
    "Игровая механика": "HP: 100, Stats: {...}",
    "Эмоции": "😊 Радость 7/10"
}
```

Модули могут:
- Добавлять данные в контекст
- Обрабатывать специфичную логику
- Сохранять состояние в БД

### Промпты
Системные промпты модульные:

```python
system_prompt_parts = {
    "base": "Ты - гейм-мастер...",
    "setting": "Мир: фэнтези-исекай...",
    "rules": "Правила D&D 5e...",
    "restrictions": "18+ контент разрешён",
    "format": "Отвечай JSON..."
}
```

## Безопасность

1. **Изоляция сессий**: кванты жёстко привязаны к session_id
2. **Валидация**: все входные данные проверяются Pydantic
3. **API ключи**: через .env, не в коде
4. **Логирование**: полное, но API ключи не логируются

## Производительность

### Оптимизации:

## Миграция с SQLite на PostgreSQL

1. Изменить `DATABASE_URL` в `.env`
2. Установить `psycopg2`
3. Перезапустить - таблицы создадутся автоматически
4. Экспорт/импорт данных через SQL

Код уже готов к миграции.
