## ✅ Что исправлено:

### 1. JSON формат ответа GM (КРИТИЧНО)

**Проблема:**
- DeepSeek V3.2 игнорировал инструкции и отвечал чистым текстом
- Fallback парсинг терял список квантов
- Результат: GM не запрашивал кванты в 90% ходов

**Решение:**
- Добавлен `response_format={"type": "json_object"}` в API вызов
- Это заставляет модель отвечать ТОЛЬКО в JSON формате
- Файл: `core/agents/gm_agent.py`, строка 67

### 2. Улучшен fallback парсинг (ВАЖНО)

**Новые паттерны извлечения квантов:**

1. **Pattern 3: Извлечение из маркеров**
   ```python
   # Находит =Имя= в тексте
   marker_matches = re.findall(r'=([А-Яа-яA-Za-z0-9_]+)=', content)
   ```

2. **Pattern 4: Поиск JSON в тексте**
   ```python
   # Находит "quants": [...] где угодно
   quants_match = re.search(r'["\']quants["\']\s*:\s*\[([^\]]+)\]', content)
   ```

**Результат:**
- Даже если модель ответит текстом, система извлечёт кванты
- Файл: `core/agents/gm_agent.py`, строки 178-199

### 3. Исправлена логика первого хода (КРИТИЧНО)

**Проблема:**
- Система проверяла наличие запрошенных квантов
- Если квантов не было → считала что это первый ход
- На ходу 19 загрузила начальные данные заново

**Решение:**
- Теперь проверяется `current_turn` в сессии
- Начальные данные загружаются ТОЛЬКО если `current_turn == 0`
- Файл: `core/orchestrator.py`, строки 145-179

**До:**
```python
if not recent_turns or not recent_turns[0].requested_quants:
    # First turn - load initial quants
    logger.info("First turn detected - loading initial quants")
```

**После:**
```python
if db_session.current_turn == 0:
    # First turn - load initial quants
    logger.info("First turn (current_turn=0) - loading initial quants")
```
