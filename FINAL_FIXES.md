### 1. Критическая ошибка `/retry` ✅

**Проблема:**
```
pydantic_core._pydantic_core.ValidationError: 1 validation error for Message
text
  Instance is frozen [type=frozen_instance]
```

**Причина:**
- Попытка изменить frozen (неизменяемый) объект Pydantic Message
- `fake_msg.text = last_msg` вызывала ошибку

**Решение:**
- Полностью переписана логика `/retry`
- Теперь НЕ создаёт fake message
- Напрямую вызывает API с сохранённым текстом
- Включает полную обработку ошибок и retry логику

**Файл:** `telegram/bot.py`, строки 157-250

**Новая логика:**
```python
async def cmd_retry(self, message: Message, state: FSMContext):
    # Получаем сохранённое сообщение
    last_msg = self.last_user_messages.get(user_id)

    response = await client.post(
        f"{API_BASE_URL}/sessions/{session_id}/messages",

        }
```

### `/retry` - Повтор последнего запроса

**Когда использовать:**
- Telegram API таймаутит
- Ответ не доставлен
- Ошибка при отправке

**Как работает:**
1. Бот сохраняет каждое ваше сообщение
2. При `/retry` отправляет сохранённое сообщение в API
3. Получает ответ GM
4. Пытается доставить 3 раза
5. Если не удалось - показывает ошибку с предложением `/retry` снова

**Пример:**
```
Вы: Атакую дракона мечом
Бот: ❌ Не удалось доставить ответ

Вы: /retry
Бот: 🔄 Повторяю запрос: "Атакую дракона мечом"
Бот: ⏳ Готовлю ответ...
Бот: 🎲 Ход #5
     Ты замахиваешься мечом...
```
